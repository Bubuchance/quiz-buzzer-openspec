# 08 Explore 紀錄：直接串接雲端 Google Sheets

> 來源：課程公告【期末專題補充說明】關於 Guided Notes 的串接方式（11-17，助教陳彥福）
> 「系統需直接串接**自己雲端線上的 Google Sheets** 進行讀寫，而非下載成 .xlsx 檔在本地端離線處理。」

## 使用的提示詞

```text
/openspec explore
老師公告 Guided Notes 必須直接串接雲端 Google Sheets 讀寫，不能下載 xlsx 離線處理。請檢查目前 guided-notes
主規格與程式哪些地方違反這個規定，比較 Google Sheets API 的授權方式（服務帳號、OAuth），並提出不洩漏金鑰的做法。
本次只討論，不寫程式。
```

## 目前違反規定的地方

| 位置 | 目前做法 | 問題 |
|------|----------|------|
| 匯入（上傳） | 老師上傳下載好的 .xlsx | 離線處理，違反公告 |
| 匯入（網址） | 用公開網址下載 xlsx 再解析 | 本質上仍是下載 xlsx 離線處理 |
| 匯出 | 產生 .xlsx 讓老師下載再手動匯入 Google Sheets | 沒有直接寫回雲端 |

## 授權方式比較

| 方式 | 老師要做的事 | 金鑰 | 優缺點 |
|------|--------------|------|--------|
| **服務帳號（採用）** | 把試算表「共用」給服務帳號的 email（編輯者） | 一個 JSON 金鑰檔，放在本機、路徑用環境變數指定，`.gitignore` 排除 | 不用每次登入；本機執行最簡單；Demo 穩定 |
| OAuth 使用者登入 | 每次在瀏覽器登入 Google 並同意權限 | OAuth client 檔＋存下來的 token | 要設定同意畫面與測試使用者，步驟較多 |
| 公開網址＋Apps Script | 部署腳本 | 無 | 要在每份試算表另外寫腳本，換一份學習單就要重做 |

## 已確認規則與合理預設

1. 老師貼上自己 Google Sheets 的網址（或試算表 ID），系統用 Google Sheets API 即時讀取所有工作表，再用既有的欄位標題規則解析。
2. 寫回：搶答「已結束」後，老師按「寫回 Google Sheets」，系統直接修改雲端試算表的作答格。
3. 寫回前重新讀一次雲端試算表；如果題目結構（題號、題組小題數）跟匯入時不同，拒絕寫回並請老師重新匯入，避免寫錯格子。
4. 單題：作答格寫入答案；無人成功的單題寫入空白（確保「保持空白」，重設後再玩一輪也不會殘留舊答案）。
5. 題組：寫成「（1）答案」——保留（k）標示、答案接在後面。這樣寫回後的試算表仍可再次匯入、再次寫回；無人成功的題組只留（k）。（**需通知 SpecKit 組**）
6. 一律以「純文字」寫入（Sheets API 的 RAW 模式），答案以 `=` 開頭也不會變成公式。
7. 金鑰檔路徑由環境變數 `GOOGLE_SERVICE_ACCOUNT_FILE` 指定，預設 `credentials/service-account.json`；`credentials/` 整個資料夾不進 repo。
8. 老師頁顯示服務帳號 email 與設定狀態，並把「沒有權限」「找不到試算表」「尚未設定金鑰」翻成可理解的中文訊息。
9. 移除 .xlsx 上傳與 xlsx 匯出；結果 CSV 匯出保留（那是活動紀錄，不是 Guided Notes）。

## 驗收情境

1. 尚未放金鑰檔 → 老師頁顯示「尚未設定 Google 服務帳號」與設定說明連結；匯入時顯示同樣訊息。
2. 試算表沒共用給服務帳號 → 匯入顯示「請把試算表共用給 xxx@…iam.gserviceaccount.com（編輯者）」。
3. 貼上老師範本網址 → 匯入 6 題／4 題。
4. 搶答中按寫回 → 拒絕（需先結束）。
5. 結束後寫回 → 雲端試算表第 1 題作答格出現成功答案、題組格出現「（1）答案」、無人成功的單題為空白。
6. 匯入後有人在試算表刪掉一題再寫回 → 拒絕並請重新匯入。
7. 寫回後再匯入同一份試算表 → 仍可正確辨識題數與題組。
