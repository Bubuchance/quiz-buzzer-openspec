# 01 Explore 紀錄：課堂搶答系統需求釐清

> 對應 OpenSpec 流程的 **Explore（探索）** 階段。Explore 只討論、不寫程式、不建立 OpenSpec artifacts。
> 這份檔案是把討論結論整理下來，給後續 `propose` 使用，也方便 SpecKit 小組對照，確保兩組功能一致。

## 使用的提示詞（可貼給 Codex / Claude Code）

```text
/openspec explore
請先查看專案與 OpenSpec，再探索「課堂搶答系統」需求。需求來源是 2026 軟體工程期末專題說明：
老師匯入 Guided Notes（Google Sheets 填空式學習單）題目，開啟／結束搶答，檢視作答狀況與結果，
並把搶答成功組別的答案匯出回原 Guided Notes 的填空格；學生以組別為單位送出答案，搶答結束前
看不到其他組作答，最快送出者為搶答成功，所有使用者的活動階段要同步。額外功能做：題組、CSV 匯出、
更公平的搶答機制。不可用靜態儲存格位置匯入／匯出（助教會換一份 Guided Notes 測試），不可洩漏金鑰，
只需本機執行。請整理已確認規則、合理預設與驗收情境；本次只討論，不寫檔、不實作。
```

## 已確認規則（來自老師的作業說明）

| # | 規則 |
|---|------|
| R1 | 使用者分為「老師」與「學生」兩種角色 |
| R2 | 老師可匯入 Guided Notes 題目；題數須與 Guided Notes 一致；只需題號，不必匯入題目敘述 |
| R3 | 老師可開啟、結束搶答 |
| R4 | 老師可即時檢視作答狀況與搶答結果 |
| R5 | 老師可把搶答成功組別的答案寫回原 Guided Notes 的**填空格** |
| R6 | 學生在搶答開始後才能作答；以「組別」為單位送出 |
| R7 | 學生在搶答結束前看不到其他組別的作答狀況；結束後可檢視結果 |
| R8 | 每題最快送出的組別為搶答成功 |
| R9 | 所有使用者的活動階段（未開始／搶答中／已結束）要同步 |
| R10 | 不能用固定儲存格位置匯入／匯出（例如寫死 C19） |
| R11 | 不可在程式碼或 repo 洩漏密碼、金鑰 |
| R12 | 只需在本機執行模擬，不需架設對外伺服器 |

## 合理預設（作業沒有規定，由我們決定，已在文件中標註）

| # | 預設 | 理由 |
|---|------|------|
| D1 | Guided Notes 的填空格用**佔位符**標記：單題 `{{3}}`，題組第 3 題的第 1、2 小題 `{{3-1}}`、`{{3-2}}` | 作業允許「在填空格加上佔位符」。系統掃描整份試算表所有工作表、所有儲存格找佔位符，所以換一份 Guided Notes 也能用，不依賴固定位置（R10） |
| D2 | 匯入方式：上傳 `.xlsx`（Google Sheets →「檔案 → 下載 → Microsoft Excel」）或貼上「知道連結的人皆可檢視」的 Google Sheets 網址 | 不需要 Google API 金鑰就能完成，符合 R11；網址模式不用手動下載 |
| D3 | 匯出：產生一份把答案寫進填空格的 `.xlsx`（保留原本格式），老師再到 Google Sheets「檔案 → 匯入 → 取代試算表」 | 直接寫回 Google Sheets 需要 OAuth 憑證，會增加洩漏金鑰的風險與設定難度 |
| D4 | 老師用「老師通行碼」登入；通行碼由環境變數 `TEACHER_PASSCODE` 設定，未設定時啟動時隨機產生並顯示在終端機 | 不把密碼寫進 repo（R11） |
| D5 | 老師設定組數（預設 4 組，最多 20 組）；學生輸入名字並選擇組別加入 | 簡單、Demo 時好操作 |
| D6 | 登入身分存在瀏覽器分頁（sessionStorage），同一個瀏覽器開不同分頁可以分別當老師、第 1 組、第 2 組 | Demo 影片需要同時展示老師與至少 2 組畫面 |
| D7 | 每組每個搶答單位（單題或整個題組）只能送出一次，送出後不能修改；答案去除前後空白後不得為空 | 避免「先送空白搶時間、再改答案」 |
| D8 | 搶答順序以**伺服器收到的先後**為準 | 不信任各台電腦的時鐘 |
| D9 | 資料只存在記憶體，重新啟動伺服器後清空 | 作業不要求保存；簡化 |
| D10 | 匯出時尚未有人搶答成功的題目保留原佔位符 | 老師一看就知道哪些題沒人答，也能再匯入一次 |
| D11 | 公平模式（老師可開關）：第一組送出後的 N 秒（預設 3 秒）內送出的組別都算「同一波」，同一波中**已成功題數較少**的組別優先，同數再比時間 | 鼓勵還沒成功過的組別參與（額外功能） |

## 驗收情境（之後寫進 spec 的 Scenario）

1. 老師用正確通行碼登入成功；錯誤通行碼被拒絕。
2. 學生選組加入；未匯入題目時顯示「等待老師匯入題目」。
3. 匯入含 5 題單題的 Guided Notes → 系統顯示 5 題；匯入含題組的 → 題組顯示為一個搶答單位、內含多個小題。
4. 匯入沒有任何佔位符、題號重複或跳號的檔案 → 顯示錯誤，不改變目前題目。
5. 換一份佔位符位置不同的 Guided Notes → 仍能正確匯入與匯出（證明非固定位置）。
6. 老師開啟搶答 → 所有已開啟的頁面在 2 秒內同步顯示「搶答中」。
7. 搶答中，第 2 組先送第 1 題、第 1 組後送 → 第 2 組成功；第 1 組順位 2。
8. 搶答中學生看不到別組送出了什麼（連送出數量也看不到）；老師即時看到全部。
9. 送出空白答案、題組少填一格、重複送出、搶答未開始就送出 → 皆被拒絕。
10. 老師結束搶答 → 所有頁面同步顯示「已結束」，學生看到每題成功組別與答案。
11. 匯出 Guided Notes → 成功答案出現在原本佔位符所在的儲存格，其他文字與格式不變。
12. 匯出 CSV → 含題號、小題、組別、答案、順位、是否成功。
13. 公平模式開啟時，在時間窗內較晚送出但成功題數較少的組別會被選為成功。
