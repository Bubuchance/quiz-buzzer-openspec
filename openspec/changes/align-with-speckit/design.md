# Design

## Context

第一版架構（見 `openspec/changes/archive/2026-11-05-build-classroom-buzzer/design.md`）維持不變：FastAPI REST 寫入、WebSocket 推送依角色過濾的快照、規則集中在 `activity.py`。本 change 只改規則與解析方式（動機見 proposal.md）。

## Goals / Non-Goals

**Goals:**
- 行為與 `docs/speckit/feature-alignment-原始版.md` 一致。
- 學習單解析仍完全動態：不依賴標題列位置、欄位順序或工作表名稱。

**Non-Goals:**
- 不改 Google Sheets 存取方式（仍為上傳 xlsx／公開網址下載，待與 SpecKit 組確認）。
- 不保留舊 `{{n}}` 佔位符格式的相容性。

## Decisions

### D1. 學習單解析：找標題列 → 逐列狀態機
- 依工作表順序，找第一個「某一列同時有文字為『題號』與『作答』的儲存格」的工作表（比對前移除所有空白）。記下兩欄的欄號。
- 從標題列下一列逐列讀取：
  - 題號欄可解析為整數（接受 `3`、`3.0`、`"3"`、`"3."`、`"第3題"`）→ 新題目。作答欄若以（k）開頭即為題組第 k 小題，否則為單題，填空格為該列作答格。
  - 題號欄為空、作答欄以（k）開頭 → 屬於上一題的題組；上一題不是題組（或沒有上一題）則報錯。
  - 其他列（空白、段落標題）→ 略過，並結束目前題組的接續。
- （k）的正規表示式：`^\s*[（(]\s*(\d+)\s*[）)]`，全形半形括號皆可。
- 解析結果記錄每個填空格的座標，匯出時用**同一個解析函式**重新取得座標，確保匯入匯出規則一致。
- **替代方案**：保留 `{{n}}` 並同時支援兩種格式 → 兩組行為不一致且測試量加倍，不採用。

### D2. 匯出寫回
- 單題：作答格整格寫入答案。
- 題組：把作答格開頭的（k）標示（含後面的底線與空白）換成答案，其餘文字保留。
- 無人成功：不動該格（單題原本就是空白，題組保留（k））。
- 寫入後設 `data_type = "s"`，避免以 `=` 開頭的答案被當成公式。

### D3. 階段標籤
- 內部仍保留 `no_questions` 狀態（用來判斷能否開啟、重設），但畫面標籤與 `ready` 相同，都顯示「準備中」，學生頁說明文字另外提示「等待老師匯入題目」。
- **理由**：對外符合三階段規則，內部不需改動判斷邏輯。

### D4. 公平順位：收到當下固定「已成功題數」
- 每筆送出記錄 `prior_wins`：收到時，以當時所有已收到的送出計算暫定成功者（依有效時間），數出該組已成功幾題。
- 有效時間 = `at + prior_wins × 延遲量`（公平模式關閉時 = `at`）。每題依（有效時間, 收到序號）排序，第一名成功，順位即排序名次。
- `prior_wins` 一律依公平規則計算並儲存，所以老師結束後才切換公平模式時，結果仍可重算且一致。
- **理由**：有效時間在收到時固定，不會因之後的送出而改變，學生好理解、測試可重現。
- **替代方案**：結束時一次性迭代計算 → 「已成功題數」的定義循環依賴，結果難以解釋。

### D5. 倒數計時：伺服器端計時 + 回合編號
- `time_limit`（秒，0 = 不限時）。開啟時記錄 `deadline` 與遞增的 `round_id`。
- `main.py` 開啟搶答時建立 `asyncio` 背景工作，睡到 deadline 後呼叫 `activity.expire(round_id)`；回合編號不同（已手動結束或已重設）就不做事。成功結束後廣播。
- 送出時也先檢查 deadline，時間已到就先自動結束再拒絕，避免背景工作稍晚執行時仍收到答案。
- 快照提供 `remaining_seconds`（伺服器計算）；前端收到後以本機時鐘倒數顯示，每次新快照重新校正。

### D6. 標記對錯與計分板
- `marks: dict[題號, "correct" | "wrong"]`，只在「已結束」可修改，且該題必須有成功組別；重設、重新匯入時清除。
- 計分板每列：組別、得分（標「對」的成功題數）、成功題數；排序（-得分, -成功題數, 組別）。
- API：`POST /api/teacher/mark {number, mark}`，mark 為 `"correct"`、`"wrong"` 或 `null`。

### D7. CSV
- 每筆送出一列：題號、組別、答案、搶答順位、是否搶答成功（是／否）、送出時間。
- 每筆送出另存牆上時間 `wall = time.time()`，以本機時區格式化為 `YYYY-MM-DD HH:MM:SS.mmm`。

### D8. 學生進度
- 學生快照加入 `progress: {submitted, total}`，只由本組送出計算。

### D9. 協作方式
- 本 change 在 `feature/align-with-speckit` 分支開發，推上 GitHub 後以 Pull Request 合併回 `main`（作業加分項目）。

## Risks / Trade-offs

- [老師範本的標題文字若不是剛好「題號」「作答」（例如「作答區」）] → 錯誤訊息會提示需要的標題文字；與 SpecKit 組同步確認範本。
- [題號欄出現非數字的文字（例如「一、」）會被當成非題目列略過] → 匯入後顯示題目清單與位置供老師核對題數。
- [背景計時工作在伺服器重啟時遺失] → 資料本來就只存在記憶體，重啟即全部清空，無影響。
- [公平模式「收到當下」的暫定結果可能在之後被別組有效時間更早的答案翻盤] → 這是公式本身的特性；`prior_wins` 不追溯修改，規則固定、可說明。

## Migration Plan

舊格式學習單需加上「題號」「作答」標題列並把 `{{n}}` 改為空白作答格、`{{n-k}}` 改為（k）。範例檔 `samples/` 會一併更新。

## Open Questions

- 延遲量預設 3 秒、組數上限 20、Google Sheets 存取方式等待 SpecKit 組回覆；調整只需改常數，不影響本設計。
